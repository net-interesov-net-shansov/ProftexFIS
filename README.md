# Экспорт заявлений абитуриентов в ФИС ГИА

Скрипт читает реестр заявлений абитуриентов из Excel-файла, формирует конкурсные группы, генерирует XML-пакет в формате, ожидаемом ФИС ГИА и приёма, и опционально отправляет его на сервер.

## Возможности

- Загрузка данных из Excel-реестра (по умолчанию `xlsx/reestr.xlsx`, путь можно переопределить флагом `--input`).
- Проверка наличия всех обязательных столбцов в реестре перед обработкой — при отсутствии хотя бы одного скрипт останавливается с понятным сообщением, а не падает с `KeyError` посреди генерации.
- Фильтрация записей — обрабатываются только абитуриенты с гражданством «Российская Федерация».
- Автоматический расчёт конкурсных групп (по специальности, форме обучения и виду финансирования) с сохранением их в `config.txt` (раздел `Konkursy:`), либо использование уже сохранённых групп, если они там есть.
- Генерация XML-пакета (`AuthData`, `PackageData` → `Applications` → `Application` со всеми вложенными блоками: данные абитуриента, документ, удостоверяющий личность, документ об образовании и т.д.).
- Форматирование значений: СНИЛС, пол, регион, даты, серии/номера паспорта и аттестата с ведущими нулями.
- Ранее захардкоженные идентификаторы (регион школы/вуза, тип гражданства, страна выдачи документа, коды региона по умолчанию и для Москвы) вынесены в `config.txt` с разумными значениями по умолчанию.
- Логирование через модуль `logging` вместо `print` — с уровнями INFO/DEBUG/WARNING/ERROR и отметками времени; для заявлений без найденной конкурсной группы выводится предупреждение.
- Сохранение результата в файл `output_<ГГГГММДД_ЧЧММСС>.xml`.
- Отправка сформированного пакета на сервер по HTTP POST — интерактивно (вопрос в консоли) или неинтерактивно через CLI-флаги `--send` / `--no-send`, что удобно для автоматизированных сценариев (cron, CI).

## Требования

- Python 3.9+
- Зависимости из `requirements.txt`:

```
pip install -r requirements.txt
```

## Структура файлов проекта

```
.
```

## Формат config.txt

Файл представляет собой набор пар `Ключ: Значение`, по одной на строку, плюс отдельный раздел конкурсных групп после строки `Konkursy:`.

Пример:

```
Login: user_login
Password: user_password
Server: https://example.gov.ru/api/upload
UID_PK: 000000
SchoolCertRegionID: 77
NationalityTypeID: 1
ReleaseCountryID: 1
MoscowRegionID: 77
DefaultRegionID: 1000
Konkursy:
000000_1 09.03.04 Программная инженерия Очная Бюджет
000000_2 09.03.04 Программная инженерия Очная Контракт
```

Обязательные ключи:

| Ключ       | Назначение                                                   |
|------------|---------------------------------------------------------------|
| `Login`    | Логин для авторизации в ФИС ГИА (используется в XML `AuthData`) |
| `Password` | Пароль для авторизации                                        |
| `Server`   | Полный URL эндпоинта для отправки XML-пакета                  |
| `UID_PK`   | Префикс для генерации ID конкурсных групп                     |
| `Konkursy` | Заголовок раздела; при первом запуске заполняется автоматически |

Опциональные ключи (ранее захардкоженные значения; если не указаны — берутся значения по умолчанию, приведённые ниже):

| Ключ                 | Назначение                                                       | По умолчанию |
|----------------------|--------------------------------------------------------------------|--------------|
| `SchoolCertRegionID` | `RegionId` в блоке документа об образовании (`SchoolCertificateBasicDocument`) | `77` |
| `NationalityTypeID`  | Тип гражданства в блоке удостоверения личности                     | `1` |
| `ReleaseCountryID`   | Страна выдачи документа, удостоверяющего личность                  | `1` |
| `MoscowRegionID`     | Код региона, если в «Место регистрации» встречается «Москва»       | `77` |
| `DefaultRegionID`    | Код региона для всех остальных случаев                             | `1000` |

Если после `Konkursy:` уже есть строки — скрипт использует их как готовые конкурсные группы и не пересчитывает их заново. Если строк нет — группы будут посчитаны из данных Excel и дописаны в файл.

## Ожидаемые столбцы в reestr.xlsx

Скрипт ожидает в Excel-файле (лист по умолчанию) как минимум следующие столбцы:

- `Номер`, `Источник`
- `Фамилия`, `Имя`, `Отчество`, `Пол`, `СНИЛС`, `Электронная почта`
- `Место регистрации`, `Полный адрес`, `Квартира`
- `Изменение статуса`
- `Тип ГИА`
- `Специальность`, `Форма обучения`, `Финансирование`
- `Серия ДУЛ`, `Номер ДУЛ`, `Код подразделения ДУЛ`, `Дата выдачи ДУЛ`, `Кем выдан ДУЛ`
- `Дата рождения`, `Гражданство`
- `Серия документа об образовании`, `Номер документа об образовании`, `Дата выдачи документа об образовании`
- `Организация, выдавшая документ об образовании (школа)`, `Год окончания`, `Средний балл`

## Запуск

Интерактивный режим (по умолчанию задаёт вопрос об отправке в конце):

```
python main.py
```

С явным указанием файла реестра и подробным логированием:

```
python main.py --input xlsx/reestr.xlsx -v
```

### CLI-флаги

| Флаг              | Назначение                                                                 |
|-------------------|------------------------------------------------------------------------------|
| `--input PATH`    | Путь к файлу реестра Excel (по умолчанию `xlsx/reestr.xlsx`)                 |
| `--send`          | Сформировать XML и сразу отправить его на сервер без интерактивного вопроса  |
| `--no-send`       | Только сформировать XML, не отправлять и не спрашивать (для проверки/CI)     |
| `-v`, `--verbose` | Подробное логирование (уровень DEBUG)                                        |

`--send` и `--no-send` взаимоисключающие; если ни один из них не указан, скрипт задаёт интерактивный вопрос («д»/«н»), как раньше.

Порядок работы скрипта:

1. Читает Excel-файл (`--input` или `xlsx/reestr.xlsx` по умолчанию) и проверяет наличие всех обязательных столбцов — если чего-то не хватает, выполнение останавливается с описанием проблемы.
2. Отфильтровывает записи с гражданством «Российская Федерация».
3. Проверяет `config.txt` на наличие уже рассчитанных конкурсных групп; при отсутствии — считает их и дописывает в файл.
4. Формирует XML-документ и сохраняет его как `output_<дата_время>.xml` в текущей директории.
5. В зависимости от флагов — отправляет пакет автоматически (`--send`), не отправляет (`--no-send`), либо интерактивно спрашивает пользователя.

Весь ход выполнения (сколько записей загружено/отфильтровано, какие конкурсные группы найдены, результат отправки и т. д.) выводится в лог с отметками времени вместо простого `print`.

## Отправка на сервер

Отправка выполняется POST-запросом с телом — содержимым XML-файла и заголовком `Content-Type: text/xml`. Таймаут запроса — 30 секунд. Результат (код ответа, тело ответа) пишется в лог; отдельно обрабатывается код 404 (неверный URL в `config.txt`), таймаут и ошибки соединения.

## Известные особенности реализации

- Некоторые значения (серия/номер паспорта, номер аттестата) дополняются ведущими нулями до фиксированной длины (4, 6 и 14 символов соответственно).
- Регион определяется упрощённо: по подстроке «Москва» в поле «Место регистрации»; коды региона задаются через `MoscowRegionID`/`DefaultRegionID` в `config.txt`.
- Пол определяется по наличию подстроки «женский»/«ж» в значении, иначе считается мужским.
- Идентификаторы `SchoolCertRegionID`, `NationalityTypeID`, `ReleaseCountryID` берутся из `config.txt` (см. таблицу выше); значения по умолчанию соответствуют прежнему захардкоженному поведению и рассчитаны на граждан РФ (что соответствует применяемому фильтру).
- Если для заявления не найдена подходящая конкурсная группа, в лог выводится предупреждение, а `CompetitiveGroupUID` в XML останется пустым — такие места стоит проверять вручную перед отправкой.
- Пароль и логин хранятся в открытом виде в `config.txt` — храните файл в защищённом месте и не публикуйте его в общедоступных репозиториях.

## Возможные доработки

- Запись логов в файл в дополнение к консоли (например, через `logging.FileHandler`).
- Более строгая валидация значений внутри столбцов (даты, СНИЛС, ФИО), а не только наличия самих столбцов.
- Поддержка нескольких листов/файлов реестра за один запуск.
- Автоматические повторные попытки (retry) при отправке пакета в случае временных сетевых ошибок.
